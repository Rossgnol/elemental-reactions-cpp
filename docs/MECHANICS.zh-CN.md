# 元素反应机制与工程映射

## 1. 模型范围

工程把元素系统分成四层：

1. **攻击是否附着元素**：由攻击自己的 ICD 决定；未附着的元素伤害不会触发反应。
2. **元素量状态机**：元素附着、自然衰减、反应消耗、共存状态。
3. **反应产物**：独立伤害、攻击倍率、基础伤害加值、控制状态、结晶盾或草原核。
4. **最终伤害**：伤害加成、暴击、防御、抗性以及反应倍率。

核心忠实实现通用的七元素规则与 5.2 后调整过的剧变倍率。6.x 起的月反应由特定角色被动把普通反应转换而来，因此公共伤害公式已经提供，但“队伍中是否存在转换角色”“消耗露滴”等角色专属逻辑留给游戏层。7.0 新加入的星辉反应仍高度依赖指定角色与版本数据，本版没有用未经稳定验证的数据硬编码。

## 2. 元素关系

| 组合 | 反应 | 类别 | 主要结果 |
|---|---|---|---|
| 火 + 水 | 蒸发 | 增幅 | 触发攻击乘 1.5 或 2.0，再受精通修正 |
| 火 + 冰 | 融化 | 增幅 | 触发攻击乘 1.5 或 2.0，再受精通修正 |
| 火 + 雷 | 超载 | 剧变 | 独立火伤与击退 |
| 雷 + 水 | 感电 | 剧变/共存 | 独立雷伤；水雷同时存在并周期结算 |
| 雷 + 冰 | 超导 | 剧变 | 独立冰伤；物理抗性降低 40%，持续 12 秒 |
| 水 + 冰 | 冻结 | 状态 | 生成冻结元素；钝击可触发碎冰 |
| 风 + 火/水/雷/冰 | 扩散 | 剧变 | 对应元素伤害，并可向其他目标传播元素 |
| 岩 + 火/水/雷/冰 | 结晶 | 产物 | 生成对应元素晶片，拾取后形成盾；同目标有 1 秒反应冷却 |
| 火 + 草 | 燃烧 | 剧变/共存 | 周期火伤与燃烧元素 |
| 水 + 草 | 绽放 | 两阶段剧变 | 生成草原核；超时爆炸，或进入超/烈绽放 |
| 雷 + 草 | 原激化 | 两阶段增伤 | 生成原激化；后续雷为超激化、草为蔓激化 |
| 雷 + 草原核 | 超绽放 | 剧变 | 追踪型草伤 |
| 火 + 草原核 | 烈绽放 | 剧变 | 范围草伤 |

草与冰不直接反应，可以共存；草不能被风扩散，也不能和岩结晶。风和岩通常只作为反应的触发元素，不能成为普通敌人身上的持续元素附着。

## 3. 元素量与衰减

技能数据提供的是攻击元素量 `U`。首次形成附着时有 20% 的附着税：

```text
初始附着元素量 = 0.8 × 攻击元素量
基础持续时间 = 2.5 × 攻击元素量 + 7 秒
每 1U 衰减耗时 = 基础持续时间 / 初始附着元素量
```

常用数值：

| 攻击元素量 | 税后附着 | 基础持续时间 | 每 1U 衰减耗时 |
|---:|---:|---:|---:|
| 1U | 0.8U | 9.5s | 11.875s/U |
| 1.5U | 1.2U | 10.75s | 8.9583s/U |
| 2U | 1.6U | 12s | 7.5s/U |
| 4U | 3.2U | 17s | 5.3125s/U |

同元素重复命中不是简单相加。新税后元素量更大时，当前量被提高到新值；通常保留首次附着确定的衰减速率。火元素自 3.0 起是例外：新应用确实改变元素量时，会采用新应用的衰减速率。`TargetState` 保存了当前量与每 U 衰减时间，`advance()` 进行连续时间衰减。

## 4. 反应消耗倍率

普通规则是：

```text
反应后附着量 = 原附着量 - 触发攻击元素量 × 消耗系数
```

| 触发方向 | 系数 | 说明 |
|---|---:|---|
| 火触发水、冰触发火 | 0.5 | 逆蒸发/逆融化，伤害倍率 1.5 |
| 水触发火、火触发冰 | 2.0 | 正蒸发/正融化，伤害倍率 2.0 |
| 水触发草 | 0.5 | 水是绽放中的弱触发元素 |
| 草触发水 | 2.0 | 草是绽放中的强触发元素 |
| 超载、超导、原激化 | 1.0 | 等量消耗 |
| 扩散、结晶 | 0.5 | 风/岩触发 |

触发量大于剩余附着量时，附着清零；普通反应不会把“多出的触发量”自动转成新附着。感电、燃烧等共存状态是例外。

## 5. 特殊共存状态

### 感电

水和雷同时保留为附着。首次触发立即结算，之后通常每 1 秒结算一次；每次有效伤害从水、雷各消耗 0.4U。任一元素耗尽后感电结束，另一元素仍可留下。火命中水雷共存目标时可在同一攻击中同时触发蒸发与超载。

### 冻结与碎冰

冻结元素量与双方较小元素量有关：

```text
冻结量 = 2 × min(原附着当前量, 触发攻击元素量)
冻结时长 = 2 × sqrt(5 × 冻结量 × (1 - 冻结抗性) + 4) - 4
```

冻结衰减初速度为 `0.4U/s`，加速度为 `0.1U/s²`。钝击先碎冰，造成独立物理伤害，再由攻击的元素部分处理暴露出来的底层元素。

### 原激化

雷草按 1:1 消耗并生成原激化：

```text
原激化量 = min(雷元素量, 草元素量)
持续时间 = 原激化量 × 5 + 6 秒
```

后续雷、草分别触发超激化、蔓激化，二者不会消耗原激化。原激化可以和雷、草、冰共存；遇到水或火时按草元素处理，可被消耗产生绽放或燃烧。

### 燃烧

燃烧生成固定 2U、不自然衰减的燃烧元素，它表现得像火元素；底层火、草仍存在。伤害每 0.25 秒结算一次，燃烧每 2 秒重新施加 1U 火。底层草采用特殊消耗速率：

```text
草消耗速度 = max(0.4U/s, 草自然衰减速度 × 2)
```

燃烧或底层草任一耗尽都会结束。重新施加火/草会把后续燃烧伤害的归属更新为最后施加者；重新施加草会覆盖底层草量。

### 草原核

绽放生成草原核，6 秒后爆炸。场上已有 5 个核心时再生成一个，最早的核心立即爆炸。火/雷命中核心分别触发烈绽放/超绽放，伤害读取火/雷触发者的等级、精通与反应加成。引擎显式暴露 `trigger_dendro_cores()`，范围、位置和命中哪些核心由游戏世界层决定。

## 6. 伤害模型

### 增幅反应

```text
增幅倍率 = 基础倍率 × (1 + 2.78×精通/(精通+1400) + 反应加成)
```

基础倍率是正向 2.0、逆向 1.5。它直接乘到触发攻击的最终伤害链中，所以攻击力、倍率、伤害加成、暴击、防御和抗性仍然有效。

### 剧变反应

```text
剧变伤害 = 反应倍率 × 等级系数
         × (1 + 16×精通/(精通+2000) + 反应加成)
         × 抗性乘区
```

它通常不能暴击，并忽略攻击力、普通伤害加成和防御。5.2 后使用的倍率：

| 反应 | 倍率 | 伤害元素 |
|---|---:|---|
| 燃烧 | 0.25 | 火 |
| 扩散 | 0.6 | 被扩散元素 |
| 超导 | 1.5 | 冰 |
| 感电 | 2.0 | 雷 |
| 绽放爆炸 | 2.0 | 草 |
| 超载 | 2.75 | 火 |
| 碎冰 | 3.0 | 物理 |
| 超绽放、烈绽放 | 3.0 | 草 |

### 激化加值

```text
激化基础伤害加值 = 反应倍率 × 等级系数
                 × (1 + 5×精通/(精通+1200) + 反应加成)
```

超激化倍率为 1.15，蔓激化为 1.25。这个数值先加到攻击的基础伤害区，再一起受到伤害加成、暴击、防御和抗性影响。

### 结晶盾

```text
盾值 = 结晶等级系数 × (1 + 4.44×精通/(精通+1400) + 结晶加成)
```

### 防御与抗性

```text
防御乘区 = (攻击者等级+100)
         / [(攻击者等级+100) + (目标等级+100)×(1-减防)×(1-无视防御)]
```

抗性乘区是分段函数：

```text
抗性 < 0       : 1 - 抗性/2
0 <= 抗性 < .75: 1 - 抗性
抗性 >= .75    : 1 / (4×抗性 + 1)
```

`Resolution` 分别返回 `attack_multiplier`、`additive_base_damage`、`attack_damage` 和每个反应的 `independent_damage`，因此表现层无需从一个总数反推伤害来源。

## 7. 月反应公共公式

月反应能暴击，忽略普通伤害加成和目标防御，但仍受抗性影响。精通区为：

```text
月反应精通加成 = 6×精通/(精通+2000)
```

间接月感电/月结晶分别使用 1.8/0.96 倍等级系数。对每个曾贡献对应元素的角色单独计算后，从高到低组合：

```text
最终值 = 最高 + 次高×1/2 + 第三×1/12 + 第四×1/12
```

角色天赋直接造成的月感电、月绽放、月结晶分别使用 3.0、1.0、1.6 倍，并以天赋指定的攻击/生命/防御等属性为基础。对应 API 是 `lunar_indirect_damage()` 与 `lunar_direct_damage()`。

## 8. ICD 与多人/范围边界

元素伤害不等于元素附着。默认 ICD 常见规则是同组第一次命中附着，之后满足“3 次命中”或“2.5 秒”任一条件时再次附着。`StandardIcdTracker` 只负责判断本次攻击是否应令 `Attack::applies_aura = true`。

完整多人战斗还需要空间查询与按目标的伤害 ICD。例如扩散需要把传播元素作为新的攻击发给周围目标；感电链、范围超载、一个火攻击命中多个草原核也依赖坐标和碰撞。本库返回足够的事件信息，但不虚构场景图。建议上层维护：

- 每个敌人一个 `TargetState`；
- 每个技能/命中组一个 `StandardIcdTracker` 键；
- 世界级草原核实体与空间索引；
- 按“来源角色 + 反应 + 目标”记录 0.5 秒等伤害限制；
- 动画、击退、韧性、掉落晶片和伤害飘字。

## 9. 精度说明

本实现目标是“机制可解释、数值可测试、适合继续扩展”，不是对闭源客户端逐帧反编译。已明确保留的工程化边界：

- 普通元素量、主流共存与伤害公式按公开测试资料实现；
- 冻结连续抗性记忆、命中停滞延长、极少数双扩散优先级和历史客户端 bug 没有逐帧模拟；
- 扩散的传播由事件交给世界层，单目标核心只计算本目标上的反应；
- 结晶掉落与护盾覆盖由角色/物品系统处理；
- 月反应只实现共享公式，专属角色资源和队伍转换开关由上层实现；
- 星辉反应等待稳定且可交叉验证的公开数据后再加入。
